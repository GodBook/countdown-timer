# 1.1.3 后台计时验证

日期：2026-09-14。环境：Android 16 / API 36 Google APIs x86_64 模拟器；JDK 17、compileSdk/targetSdk 36。版本号：5 / 1.1.3。

## 问题与修复

用户进一步确认：iQOO 已允许悬浮窗，但在后台既没有响铃也没有结束通知，只有回到应用后触发。这表明此前仅验证窗口不足以验证该设备上的后台计时。本次未连接用户的 iQOO，无法把具体厂商拦截原因当作已确认事实。

- 1.1.2 的计时服务受视觉模式及悬浮窗权限条件控制。本版所有模式均准备前台计时服务，窗口授权只控制窗口显示。
- 精确闹钟 PendingIntent 从广播改为直接启动前台服务，启动后先提升前台状态，再按计时标识处理完成；兼容撤销旧版广播闹钟。
- 服务等待单调时钟截止时间；运行时持有时长受限的 partial wake lock。暂停、重置、结束和服务销毁均释放，暂停和恢复会取消／重建等待。无需每秒刷新后台通知。
- 新增系统电池优化豁免入口、iQOO/vivo 后台运行说明。唤醒锁不能替代厂商后台权限，且可能增加耗电。
- 本地诊断保留最近 40 条事件，记录服务启动、闹钟派发、结束来源与延迟；用户可复制，不上传。明确区分后台完成和重新打开应用后补处理。

- Release 构建、Android Lint 与 10 项 JVM 测试通过；Lint 无错误，保留同步持久化等警告。
- 20 项 Android 集成测试全部通过，用时 154.432 秒：5 项新增后台测试、7 项计时回归、8 项弹窗回归。
- 新增后台测试不创建 Activity，并拒绝悬浮窗权限：仅响铃仍准备服务与唤醒锁；暂停／继续／重置释放和恢复唤醒锁；撤销精确闹钟仍由服务截止回调完成；停止服务后精确闹钟重新启动服务并结束；旧计时回调不能触发新计时。
- 最后增加了重新调度时撤销旧版广播闹钟的兼容清理，随后再次通过 Release 构建、Lint 和 JVM 测试；正式 APK 覆盖安装验证采用此代码。

## 正式 APK 验证

- 安装固定签名的 1.1.2，允许通知及悬浮窗，然后覆盖安装 1.1.3，安装成功。
- 在真实界面点击“允许后台持续计时”，系统出现后台运行授权对话框；确认后应用显示电池优化已豁免，系统白名单检查一致。
- 实际点击 5 秒后台测试后返回桌面，未再次打开计时器。日志记录 `activity_paused phase=RUNNING` → `finish source=service_deadline late=2ms` → `overlay_attached`，桌面截图确认独立居中弹窗。
- 截图：`screenshots/background-1.1.3-release-home.png`。签名证书 SHA-256 为 `c35247c16669cd62c2892fd54dbd2e2d0cecccc1242212cdc07f8679a99f5878`，与旧版一致。
- 正式界面选择 1 分钟、视觉提醒＋响铃，返回桌面并熄屏，系统电池优化已豁免。未唤醒屏幕及未返回应用前读取记录：`finish source=service_deadline late=9ms`，状态 FINISHED、ringing=true；RingService 前台运行，结束通知 ID 11 存在；同一时刻系统闹钟直接投递服务，旧标识去重避免二次完成。随后恢复屏幕及模拟电池状态。
- 尝试 `dumpsys deviceidle force-idle` 和 `force-idle deep` 均返回 `Unable to go deep idle; stopped at INACTIVE`。因此本轮验证覆盖熄屏，不能计为深度 Doze 通过。

## 验证边界

没有 iQOO 真机日志，不能宣称已在用户设备复现并解决所有厂商限制。更新后需允许后台持续计时，并检查系统自启动及后台运行设置。若仍有问题，应用内提醒诊断能提供下一次定位所需的触发链路，避免继续只依据模拟器弹窗做判断。

本次没有逐一重测 Android 8～15、完整主题及字体矩阵。系统强制停止和安全页面的悬浮窗限制仍由系统控制，不绕过系统授权。
